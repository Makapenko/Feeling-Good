# Рефакторинг Chapter Actions

## Текущая проблема
В `progressSlice` содержится значительная часть бизнес-логики, которая по архитектурным соображениям должна находиться в `chapterActions`. Это усложняет поддержку кода и его тестирование.

## Что нужно перенести

### 1. Логика разблокировки глав
- Сейчас находится в редюсере `completeChapter`
- Включает:
  - Определение следующей главы/подглавы для разблокировки
  - Работу с `typedChaptersData`
  - Логику определения является ли глава подглавой
  - Управление разблокировкой контента

### 2. Функция getNewlyUnlockedActivities
- Сейчас экспортируется из slice
- Определяет новые активности для разблокировки
- Логически связана с работой глав и их активностями

### 3. Логика работы с dailyProgress
- Находится в редюсерах `updateChapterProgress` и `completeChapter`
- Включает подготовку данных и валидацию
