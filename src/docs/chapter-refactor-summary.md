# Рефакторинг логики завершения глав и разблокировки контента

## Что было сделано:

### 1. Создана утилита `chapterUtils.ts`
**Где:** `src/utils/chapterUtils.ts`
**Что:** Вынесена логика определения следующих глав и активностей в отдельные функции:
- `getNextChapterToUnlock()` - определяет следующую главу для разблокировки
- `getChapterActivities()` - получает активности, связанные с главой
- `getUnlockContentForChapter()` - комбинирует логику определения контента для разблокировки

### 2. Упрощен `progressSlice.ts`
**Где:** `src/redux/slices/progressSlice.ts`
**Что:** Убрана дублирующая логика разблокировки из редьюсера `completeChapter`:
- Удалена сложная логика определения следующих глав
- Редьюсер теперь только обновляет состояние завершенной главы
- Убрана функция `getNewlyUnlockedActivities` (перенесена в утилиту)

### 3. Исправлена логика в `unlockActions.ts`
**Где:** `src/redux/actions/unlockActions.ts`
**Что:** Обновлена функция `unlockContentAfterChapter`:
- Теперь использует утилиту для определения следующего контента
- Правильно разблокирует следующую главу (а не текущую)
- Проверяет, не разблокирована ли глава уже

### 4. Улучшена архитектура
**Результат:**
- Убрано дублирование логики разблокировки
- Разделена ответственность: slice только для состояния, утилиты для бизнес-логики
- Упрощен код и улучшена читаемость
- Исправлена двойная разблокировка глав

## Как работает теперь:
1. `completeChapterAsync` вызывает редьюсер `completeChapter` (обновляет состояние)
2. Затем вызывает `unlockContentAfterChapter` (разблокирует следующий контент)
3. Логика определения следующих глав находится в утилитах
4. Разблокировка происходит только один раз
